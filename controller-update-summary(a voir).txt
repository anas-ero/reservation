What Changed:
- Added schema-aligned validation logic for both store and update:
  - core fields (title, type, price, pricing_type, location, description)
  - property details (max_guests, bathrooms, exclude_infants, allows_children)
  - rules/services/times (breakfast_included, smoking_allowed, parties_allowed, pets_allowed, check_in_*, check_out_*)
  - relations payload (amenities, custom_amenity, languages, rooms)
- Added human-readable validation labels (validationAttributes) for clearer error messages.
- Normalized type handling using a reusable type map.
- Implemented transactional relation persistence helpers:
  - metadata upsert (address, postal_code, country)
  - room save/replace
  - amenities and languages sync via pivot tables (resource_amenities, resource_languages), including creation of dictionary rows in amenities/languages.
- Updated update() logic to persist all supported schema fields, not just title/price/location/description.

Potential Side Effects:
- update() now accepts and processes many more fields, so front-end forms can update rules/amenities/languages if they send them.
- Pivot sync deletes existing links then inserts submitted ones; partial payloads that omit arrays leave existing links untouched, but sending empty arrays clears links.
